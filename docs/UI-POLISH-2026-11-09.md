# 现有界面细节优化

本轮沿用原有首页布局、配色、图标和功能入口。使用本机更新后的 `ui-ux-pro-max` 定向查询桌面焦点与操作等待反馈，并遵循 `preserve-content-lang` 保留中英文语言体系。

## 改动

- API Key 表单支持回车提交、就地验证和后端错误提示。保存期间显示等待状态并阻止重复操作，保存后清空前端及原生界面的密钥缓冲。已保存状态使用“已配置”，避免暗示已经验证网络连接。
- 开始操作增加前后端等待状态和重复触发保护。缺少密钥时聚焦实际可见的 WebView 输入框。
- 菜单在点击外部、移出焦点或选择操作后收起；Esc 返回对应入口。关闭中的设置区不会继续接收键盘操作。信号设置直接聚焦相关选项。
- 清空本次历史、恢复默认设置使用原生 HTML 确认对话框，支持取消和键盘 Esc；对话框关闭后恢复焦点。
- 扩大滑块操作区域，改善英文标签和卡片标题在窄窗口下的排版；左侧内容高度不足时可以滚动。历史状态采用轻量标签，空历史根据配置、运行和暂停状态提示下一步。
- 保留内容语言，修正试听文本的重复引号、英文 Jenny 音色标签和中文晓晓试听失败提示。

本轮不评价真实对局翻译质量或在线语音效果；验收范围为现有界面的可操作性与反馈。

## 真实启动故障与恢复

用户在正式启动时发现 `0x800700AA`。增加真实配置目录的原生诊断后，已确认故障发生在 WebView2 控制器创建阶段：当前启动环境中，AppData 下的旧目录和新目录均复现失败，项目内目录能正常渲染。原目录可写且未找到对应的残留浏览器进程，因此不能把原因简单断言为旧缓存损坏、未安装 Runtime 或编程语言问题。具体系统级限制尚未进一步归因。

现在针对这一 HRESULT 先在原目录有限重试，再切换到程序目录的 `WebView2Cache`，替换失败的控件；不删除原目录，不更改应用设置和凭据保存位置，也不关闭其他浏览器。关闭窗口会取消尚未完成的启动重试。错误页区分 Runtime 缺失与其他初始化失败，并提供重试按钮。

实际故障目录的验证已通过：前两次原目录控制器创建失败后，切换到项目内缓存成功渲染首页，原生等待状态、错误反馈、隐藏恢复和关闭测试均通过。诊断在恢复时重新查找当前 WebView 控件，避免继续观察已被替换的旧控件。新增回归覆盖成功、暂时占用、持续占用、非占用错误、恢复失败和关闭取消。

正式 Release 软件也已重新启动并保持运行：其 WebView2 浏览器使用应用目录下的独立缓存。已读取实际窗口的首页控件，并在将该窗口正常聚焦、确认位于前台后截取真实画面，目视确认首页显示成功。既有用户配色、音量、识别模式和保存偏好仍生效。
